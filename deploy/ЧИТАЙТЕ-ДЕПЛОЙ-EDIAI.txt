  ЕЖЕДНЕВНИК PWA — УСТАНОВКА НА ХОСТИНГ EDIAI.RU (AdminVPS, виртуальный хостинг)
  версия с напоминаниями в точное время и push-уведомлениями на iPhone
════════════════════════════════════════════════════════════════════

ЧТО ЭТО ТАКОЕ
  Статическая сборка приложения «Ежедневник» (PWA) для размещения по
  адресу https://ediai.ru/pwa/. Серверное приложение не требуется:
  страница и файлы — статика, данные синхронизируются через api.php
  (PHP-скрипт в этой же папке), который хранит их в файле
  storage/db.json.

  НОВОЕ: напоминания, у которых указано ВРЕМЯ, приходят на iPhone как
  системные push-уведомления — даже когда приложение закрыто. Рассылку
  делает push-sender.php — скрипт на чистом PHP БЕЗ ЗАВИСИМОСТЕЙ
  (без composer и Node.js). Он уже лежит в папке storage и запускается
  планировщиком (cron) из панели хостинга — шаг 5. SSH и VPS не нужны:
  всё делается через панель управления.

  Защита от поисковых систем уже встроена: meta noindex + заголовок
  X-Robots-Tag (.htaccess) + robots.txt.

СОСТАВ ПАПКИ
  pwa/
    index.html, _next/…, icons/…, manifest.webmanifest, sw.js — приложение
    api.php                 — сервер синхронизации и push-подписок (PHP 7.4+)
    .htaccess               — запрет индексации папки (X-Robots-Tag)
    storage/.htaccess       — запрет ПРЯМОГО доступа к файлам данных
    storage/push-sender.php — рассылка push по расписанию (чистый PHP,
                              веб-доступ к нему закрыт через .htaccess)
    (файлы storage/db.json и storage/push-subscriptions.json создадутся
     автоматически при первой синхронизации / включении уведомлений)
  push-sender/              — ЗАПАСНОЙ вариант на Node.js (если он вам
                              почему-то удобнее; для виртуального хостинга
                              достаточно PHP-варианта, см. шаг 5)

────────────────────────────────────────────────────────────────────
Шаг 1. ЗАГРУЗКА ПАПКИ НА ХОСТИНГ
────────────────────────────────────────────────────────────────────
  • Через панель AdminVPS (ISPmanager / файловый менеджер) или FTP:
    распакуйте архив и загрузите папку pwa ЦЕЛИКОМ в корневую папку
    сайта ediai.ru (document root, обычно
    /var/www/<пользователь>/data/www/ediai.ru/).
  • Результат в файловой системе: …/ediai.ru/pwa/index.html
  • Проверка: https://ediai.ru/pwa/ открывается и показывает приложение.

────────────────────────────────────────────────────────────────────
Шаг 2. PHP ДЛЯ api.php
────────────────────────────────────────────────────────────────────
  • В панели AdminVPS убедитесь, что для сайта выбран PHP 8.x
    (подойдёт и 7.4+). Обычно работает сразу, ничего настраивать не надо.
  • Проверка: откройте в браузере
      https://ediai.ru/pwa/api.php?action=status&key=5e254577c0cffc3536b691c9368b46ed
    Должен вернуться JSON: {"ok":true,"app":"ezhednik","push":true,...}
  • Если вернулась ошибка 404/500 — проверьте, что api.php лежит рядом
    с index.html и что PHP включён для папки сайта.

────────────────────────────────────────────────────────────────────
Шаг 3. ЗАЩИТА ОТ ПОИСКОВЫХ СИСТЕМ (индексаторы)
────────────────────────────────────────────────────────────────────
  Уже сделано в сборке:
    • <meta name="robots" content="noindex,nofollow"> в каждой странице;
    • заголовок X-Robots-Tag: noindex, nofollow для всей папки (.htaccess);
    • Disallow в robots.txt самой папки.
  Осталось добавить ОДНУ строку в корневой robots.txt САЙТА
  (файл …/ediai.ru/robots.txt — редактируется через файловый менеджер):

      User-agent: *
      Disallow: /pwa

  Если корневого robots.txt ещё нет — создайте его с этой строкой.
  (Примечание: Disallow запрещает обход, а noindex гарантирует выпадение
  уже проиндексированных страниц. Два правила вместе — максимальная защита.
  Ссылку на /pwa не размещайте на видимых страницах сайта и в sitemap.xml.)

────────────────────────────────────────────────────────────────────
Шаг 4. ПРОВЕРКА СИНХРОНИЗАЦИИ
────────────────────────────────────────────────────────────────────
  1. Откройте https://ediai.ru/pwa/ , создайте профиль, добавьте пару
     напоминаний.
  2. Через ~10 секунд (или сразу после закрытия приложения) на хостинге
     появится файл …/ediai.ru/pwa/storage/db.json.
  3. Прямое обращение к файлу данных должно быть ЗАПРЕЩЕНО:
     https://ediai.ru/pwa/storage/db.json → 403 Forbidden.
  4. На другом устройстве откройте тот же адрес — данные подтянутся
     автоматически (или кнопкой «Загрузить» в настройках).

────────────────────────────────────────────────────────────────────
Шаг 5. PUSH-УВЕДОМЛЕНИЯ: CRON В ПАНЕЛИ ХОСТИНГА (без SSH!)
────────────────────────────────────────────────────────────────────
  Push на iPhone устроен так: в момент, указанный в напоминании,
  КТО-ТО должен отправить уведомление в сервис Apple. Для статического
  сайта эту роль выполняет скрипт storage/push-sender.php (уже на
  месте), который раз в минуту запускается планировщиком (cron) сервера.

  5.1. В панели AdminVPS (ISPmanager) откройте раздел «Планировщик
       (cron)» → «Создать задачу».

  5.2. Заполните задачу:
       • Расписание: каждую минуту (если панель ограничивает частоту —
         минимум, который позволяет панель; доставка всё равно сработает
         с точностью до интервала cron — запас в скрипте 15 минут).
       • Исполнитель/команда — укажите команду запуска PHP-скрипта:

           /usr/bin/php /var/www/<пользователь>/data/www/ediai.ru/pwa/storage/push-sender.php

         • <пользователь> — ваш системный пользователь хостинга
           (виден в панели, путь к сайту показан в разделе «Сайты»).
         • Если /usr/bin/php не сработает, уточните путь к PHP в панели
           (обычно есть варианты php82/php83 и т.п., например
           /opt/alt/php82/usr/bin/php) или спросите поддержку AdminVPS:
           «какой путь к PHP CLI для cron?».

  5.3. Сохраните задачу. Через минуту-две в папке storage появится файл
       push-sender.log (открывается файловым менеджером панели).
       Пока уведомления не включены на телефоне, в журнале будет строка:
           push-подписок нет — уведомления ни на одном устройстве не включены
       Это нормально и означает: cron работает.

  5.4. Как это работает дальше (ничего делать не нужно):
         • раз в минуту скрипт читает файл данных (какие напоминания);
         • находит напоминания, срок которых наступил ровно сейчас
           (учитывается часовой пояс телефона);
         • отправляет push на включённые устройства через сервисы
           Apple/Google;
         • пишет журнал в push-sender.log, отметки «отправлено» — в
           push-state.json (защита от повторов).

────────────────────────────────────────────────────────────────────
Шаг 6. УСТАНОВКА НА IPHONE И ВКЛЮЧЕНИЕ УВЕДОМЛЕНИЙ
────────────────────────────────────────────────────────────────────
  Требования: iOS 16.4 или новее (на iPhone 8 и новее — обновите iOS
  в Настройки → Основные → Обновление ПО).

  1. Safari → https://ediai.ru/pwa/
  2. Кнопка «Поделиться» → «На экран „Домой“» → «Добавить».
     Это ОБЯЗАТЕЛЬНО: iOS присылает push только установленному
     приложению, из обычной вкладки Safari уведомления не приходят.
  3. Откройте приложение с иконки на главном экране.
  4. Вкладка «Ещё» → раздел «Push-уведомления» → «Включить уведомления»
     → разрешите в системном запросе iOS.
  5. Проверка: создайте дело на 2–3 минуты вперёд (укажите время!) —
     в назначенный момент придёт уведомление. Приложение может быть
     закрыто, телефон заблокирован.

  ЕСЛИ УВЕДОМЛЕНИЯ НЕ ПРИХОДЯТ:
    • Настройки iPhone → Уведомления → «Ежедневник» — включены ли;
    • включён ли «Не беспокоить» / режим фокусирования;
    • включены ли уведомления в самом приложении (Ещё → Push-уведомления);
    • в приложении настроена ли синхронизация (шаг 4) — без неё сервер не
      знает о ваших напоминаниях;
    • выполнен ли шаг 5 (cron) — загляните в storage/push-sender.log:
      строка «отправлено: … ← «название дела»» означает, что сервер всё
      сделал; если её нет в нужное время — см. «ВОЗМОЖНЫЕ ПРОБЛЕМЫ».

КЛЮЧ СИНХРОНИЗАЦИИ
────────────────────────────────────────────────────────────────────
  Ключ по умолчанию (вшит в сборку и в api.php):
      5e254577c0cffc3536b691c9368b46ed
  Он защищает файл данных от посторонних (это НЕ секретный токен —
  его утечка даёт доступ только к перезаписи файла данных).
  Чтобы сменить:
    1. Отредактируйте константу SYNC_KEY в api.php.
    2. В приложении: «Ещё» → «Синхронизация данных» → впишите новый
       ключ → «Сохранить и проверить».

────────────────────────────────────────────────────────────────────
VAPID-КЛЮЧИ (для push)
────────────────────────────────────────────────────────────────────
  Пара уже сгенерирована и вписана:
    • публичный ключ  — в api.php (константа VAPID_PUBLIC_KEY),
      приложение получает его автоматически;
    • приватный ключ  — в storage/push-sender.php (константа
      VAPID_PRIVATE_KEY; из веба недоступен благодаря .htaccess).
  Менять их НЕ нужно. Если захотите заменить пару:
    1. Выполните: npx web-push generate-vapid-keys
    2. Впишите новый ПУБЛИЧНЫЙ ключ в api.php.
    3. Впишите ту же ПАРУ (публичный + приватный) в push-sender.php.
    4. На устройствах выключите и снова включите уведомления.

────────────────────────────────────────────────────────────────────
ЗАПАСНОЙ ВАРИАНТ ОТПРАВКИ НА NODE.JS (не нужен на виртуальном хостинге)
────────────────────────────────────────────────────────────────────
  Если на хостинге доступен Node.js и он вам удобнее: папка push-sender/
  содержит то же самое в виде Node-скрипта (npm install, config.json,
  cron: /usr/bin/node push-sender.mjs). Протокол и файлы данных те же.
  Прочие детали — README внутри папки push-sender/ и комментарии в коде.

ЕСЛИ НА ХОСТИНГЕ ВДРУГ НЕТ PHP
  Запасной вариант синхронизации — Cloudflare Worker с тем же протоколом
  (worker.js в исходниках проекта), данные тогда хранятся в приватном
  репозитории GitHub. Адрес воркера указывается в настройках приложения.
  (Push при этом потребует отдельного решения — cron недоступен.)

────────────────────────────────────────────────────────────────────
ВОЗМОЖНЫЕ ПРОБЛЕМЫ
────────────────────────────────────────────────────────────────────
  • «Неверный ключ синхронизации» — ключ в приложении не совпадает с
    SYNC_KEY в api.php (сверьте в настройках приложения).
  • «api.php не отвечает за push» — на сервере старый api.php без
    push-действий; замените файл на свежий из этого архива.
  • Ошибка записи при синхронизации — права на папку storage: в панели
    выставьте 755 (или 775) для папки pwa/storage.
  • В push-sender.log пусто и нет даже строки «push-подписок нет» —
    cron не запускается: проверьте команду в планировщике (шаг 5.2) и
    путь к PHP CLI; создайте тестовую задачу с командой
    «/usr/bin/php -v >> /var/www/<пользователь>/push-php-test.log 2>&1»
    и посмотрите, что она пишет.
  • В журнале «[ошибка] отправка … HTTP …» один раз — обычно сетевой
    сбой, повторится в следующем прогоне; повторяется постоянно —
    пришлите строку журнала в поддержку/разработчику.
  • Уведомления включились, но не приходят — см. «ЕСЛИ УВЕДОМЛЕНИЯ НЕ
    ПРИХОДЯТ» выше.
  • Приложение открывается, но синхронизация «недоступна» — проверьте,
    что api.php открывается по https (сертификат домена выпущен/активен).
  • Изменили .htaccess — убедитесь, что Apache обрабатывает .htaccess
    (на AdminVPS включено по умолчанию).
